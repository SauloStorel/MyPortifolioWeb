    How I think request → response

    From request to response: each Rails layer with a single responsibility.

    1. GET /projects

      Browser

      The request reaches the server.

    2. config/routes.rb

      Routes

      resources :projects points to the right controller.

    3. ProjectsController#index

      Controller

      It only orchestrates. Dense business rules go to a service object.

    4. Project.includes(:tags)

      Model and PostgreSQL

      Queries with includes, no N+1, reusing scopes.

    5. index.html.erb

      View and Turbo

      Renders HTML; Turbo swaps only what changed.

    6. 200 OK

      Response

      Back to the browser, covered by specs.
